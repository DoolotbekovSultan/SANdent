# AGENTS.md

Flutter mobile app for a dental clinic ("SANdent"). UI text is in Russian; code identifiers and comments are in English.
Requires Flutter 3.44+/Dart 3.12+ (verified env: Flutter 3.47.0 / Dart 3.13.0).

## Source of truth

**Backend is the single source of truth.** All models, fields, endpoints come ONLY from the real API contract.
Do not invent fields. If the backend does not return something, the feature is cut or marked TODO with the missing endpoint named.

- Backend: `http://157.22.204.40/api/v1` (Django REST, Swagger 2.0). Currently **http, not https** — account for cleartext/ATS in builds.
- Swagger schema: `http://157.22.204.40/swagger.json` (78 paths, 37 definitions, verified live).
- Redoc: `http://157.22.204.40/redoc/` — for unclear contracts.
- If swagger and behavior diverge, verify with a `curl` request before coding.
- **Live requests are mandatory.** The terminal has network access to the backend. Before implementing any
  endpoint, make a real `curl` request (with a token where needed; creds in `test_credentials.md` — gitignored,
  never commit) and compare the actual response with `swagger.json` — never rely on the schema alone. If the
  live response diverges from swagger (as with `/auth/login/` and `/auth/refresh/`, whose schemas did not
  reflect the real fields), the code and this file record what the real server returned, not what the schema says.
- **JSON example in every data model.** Every file in `data/models/` carries a real backend JSON example as a
  `/// ```json` doc-comment above the class: start from the swagger response schema when present, then
  validate/complete it with a live token-authenticated `curl` call — the comment must show what the server
  really sent. Never paste real secrets/tokens into examples (truncate JWTs as `eyJ...<truncated>`). Applies
  retroactively (Auth models done) and to every new model starting with F2.

**Current UI is reference only.** Existing screens/mocks may be reused as-is ONLY where they match real backend data 1:1.
Otherwise adapt the UI to the backend, never the reverse.

## Architecture (nexo, mandatory)

- Every new feature is created via `nexo_cli feature ...` — never hand-write what the CLI generates
  (`data/` + `domain/` + `presentation/` layers). Only business logic inside generated TODOs is finished by hand.
- Use `nexo` classes instead of hand-rolled analogues: `NexoUseCase` (+ `NoParams`), `Result` (`Right`/`Left`) /
  `Failure` (sealed, `code`, RU `userMessage` by default), `NexoAsyncCubit` (+ `load()`/`retry()`/`refresh()`),
  `NexoAsyncStateBuilder` / `NexoFailureView` / `NexoEmptyView` / `NexoSkeletonList`, `showFailureSnackBar`,
  `DioClient` / `BaseRemoteDataSource` (+ `NexoAuthInterceptor`, `NexoRetryInterceptor`, `NexoLoggingInterceptor`),
  `BaseSecureStorageDataSource`, `PageChunk` / `PaginationController`, `NexoValidators`.
- Barrel imports: `package:nexo/nexo_core.dart`, `nexo_errors.dart`, `nexo_logger.dart`, `nexo_ui.dart`
  (`nexo_testing.dart` in tests only).
- **Strictness, no exceptions:** one canonical type per entity, one key per concept, one parse path per response;
  presentation works only with domain entities (never data models). Error format from backend
  (`{"field": ["текст"]}`, Russian) is handled in the shared layer, not per screen.
- Versions: `nexo 0.0.5-beta.0`, `nexo_cli 0.3.0` (globally installed). `nexo` is NOT yet in `pubspec.yaml` —
  add `nexo`, `injectable`, `freezed_annotation`, `json_annotation`, `get_it`
  (dev: `build_runner`, `freezed`, `json_serializable`, `injectable_generator`) as step F0.
- State migration: old code uses Riverpod 3 (`AsyncNotifier` + `.when(...)`); new features use
  flutter_bloc / `NexoAsyncCubit` + `NexoAsyncStateBuilder`. Both deps coexist during migration; old providers are
  deleted as their screens are replaced. No new Riverpod code.
- Navigation stays on `go_router` (`lib/app/router/app_router.dart`); `MainScreen` tabs + `AdminMainScreen` tabs stay
  until their screens are reimplemented on cubits.
- DI: replace the empty `lib/app/di/app_di.dart` placeholder with injectable/get_it (`@injectableInit`,
  `AppEnvironment.mock` / `prod` for mock vs real datasources generated by the CLI).

## Feature generation workflow (nexo_cli)

Selected defaults (deviation must be justified in the commit/PR):

- Presentation: `--async-cubit` — WHY: existing screens are already shaped as async list/object states
  (old `.when(data/loading/error)` maps 1:1 to `NexoAsyncStateBuilder` success/loading/failure); thinnest code.
  `--bloc` only for genuinely event-driven flows; `--list-cubit` for trivial static lists.
- `--freezed --injectable --mapper --mock` stay ON (defaults) — WHY: immutable entities/models, get_it wiring with
  mock/prod envs, single `toDomain()` mapping path, app stays runnable without a token in dev.
- `--list true` for collections, `--list false` for single objects (auth session, profile/me, dashboard).
- CRUD flags per real endpoints: `--get` (list), `--get-by-id`, `--create` (also reused for request/params DTOs like
  login `{username, password}`), `--update`, `--delete`. `--validators` for forms (login, patient create/update).
- `--json '{...}'` seeded from swagger definitions (exact backend field names/types, no invention).
- `--local-storage secure-storage` for auth tokens (access/refresh). `--pagination` for paged lists.
- `--ui --tests` when the screen needs pages/widgets scaffolds and planned tests.
- `--root` stays `lib/features` (default). `--overwrite` only after reviewing the diff of existing files.

Per-feature steps:

1. `nexo_cli feature <name> <flags...> --dry-run` — inspect, confirm flags fit the swagger contract.
2. Generate, then `flutter pub get` + `dart run build_runner build --delete-conflicting-outputs`.
3. Fill generated TODOs: real endpoint paths in the remote datasource, `fromJson` per swagger, mapper to entity.
   Pagination quirk (`appointments` → `{count, results}`, `patients`/`users` → bare array) is handled ONCE in a shared
   helper returning `PageChunk` (bare array = single chunk, `hasMore=false`) — no duplicated parsing code.
4. Wire the screen with `NexoAsyncStateBuilder` (`NexoSkeletonList` for loading, `NexoFailureView` + retry,
   `showFailureSnackBar` for actions). Reuse old UI widgets only after checking them against real data.
5. `flutter analyze` clean + `flutter test`; fix or rewrite touched tests.
6. Update the feature list below (status per feature).

Infra note: `nexo_cli init` scaffolds competing app shell files — do NOT run it blindly. Inspect via
`nexo_cli init --dry-run` first and adopt selectively (network/DI/logger); the existing `go_router` setup stays.

## Known backend/UI conflicts (fix first)

- **Auth**: now email+password+role picker → must become username+password; role comes from `GET /me/`
  (`doctor`/`director`/`admin`/`receptionist`), never chosen at login. JWT access/refresh + `Authorization: Bearer`.
- **User**: backend `id:int, username (required), first/last/full_name, email?, role, phone, clinic:int, is_active,
  fcm_token/device_id`. No avatar/specialization fields that the current UI shows → placeholders or cut.
- **Patient**: backend `id:int`, split names, required `date_of_birth, gender (male/female), phone`,
  `inn/snils/policy, allergies, chronic_diseases`, counters; plus `/patients/{id}/history`, `/stats`, `/search`.
  Now: `id:String, fullname, number` only.
- **Appointment**: backend `patient/doctor/clinic/date_time/duration/status
  (scheduled/in_progress/completed/cancelled/no_show/rescheduled)/sync_status/status_history` + detail objects;
  plus `/doctors/{id}/schedule`, `/available-slots`, `cancel/complete/no_show/change_status`. Now: only
  `hour/minute/title/color` with hardcoded dates. `status → color` mapping is undefined — needs a decision.
- **MedicalRecord**: backend requires `appointment + diagnosis`; procedures/materials via
  `add_procedure`/`add_material`/`remove_*`. Now: local string lists, "finish visit" is a SnackBar, history is static.
- **Materials**: `current_stock`/`total_used` are decimal-strings — parse with format validation. Statuses via
  `needs_restock`/`min_stock`, not color dots. Transactions `income/outcome/adjustment`, `add_stock/subtract_stock`.
- **Admin dashboard**: endpoints exist (`/reports/dashboard|financial|doctors`, `/appointments/statistics`,
  `/materials/statistics`, `/notifications/statistics`) but response schemas are `null` in swagger — probe via redoc
  or an authenticated request, never guess from mock layout.
- Decimal-as-string, int-vs-String ids, and the two pagination shapes are the top parsing gotchas.

## Style conventions

- Code uses Dart dot-shorthand extensively: `.center`, `.w600`, `.only(...)`, `.symmetric(...)`, `.circular(...)`,
  `.infinity` (Dart 3.12 feature). Preserve this style in new code.
- Data models mirror backend JSON keys verbatim (snake_case, e.g. `first_name`) with a file-level
  `// ignore_for_file: non_constant_identifier_names` — the DTO is a JSON mirror, no key translation bugs.
  Domain entities use idiomatic camelCase (`firstName`); the mapper translates field-by-field.
  Every data model carries a live-verified `/// ```json` example (see Source of truth).
- All text styling uses `GoogleFonts.poppins`. Loading states use `NexoSkeletonList` in new code
  (old `skeletonizer` remains only in not-yet-replaced screens).
- Brand palette: blue `0xFF2773BB`, card gray `0xFFD9D9D9`, nav background `0xFFE6E6E6`.

## Gotchas

- Directory/file typos are intentional and referenced by imports: `lib/features/spash/` (SplashScreen),
  `data/mock_respository.dart` (patients). Keep paths as-is unless renaming everywhere.
- Assets live in `assets/images/` and `assets/icons/`, already registered in `pubspec.yaml` under `assets:`.
- Generated `*.freezed.dart` / `*.g.dart` / `*.config.dart` are committed (needed for CI without codegen).
- `nexo fix` patches known freezed 3.x codegen bugs in generated files — run it if freezed output looks broken.

## Forbidden

- Inventing fields/endpoints not present on the backend.
- Copying UI without checking it against real data.
- Hand-writing what `nexo_cli` generates.
- Second implementations of entities/errors/usecases bypassing `nexo`.
